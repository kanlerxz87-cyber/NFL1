Verification

Verification here means two things: checking each dataset against the official source it came from, and building rules that make it impossible to publish an unsourced value by accident. Both are covered below.

The strongest check was not ours. Another session had independently transcribed the same official pages into data/verified/ on main. Comparing the two transcriptions: all 32 clubs match exactly on every numeric field, and all 6 published game designations match exactly on every field. Two independent readings of the same official source agreeing is far better evidence than any internal consistency check.
A second check is arithmetic: across all 32 teams, total points for equals total points against (6,246 each), and total wins equals total losses (135 each, with 2 ties). Those equalities hold only if every transcribed row is correct.
One caveat on scope. This session's branch came off the repository's initial commit, so the repository review covered that lineage only. main had already received other sessions' work. See F-012.

Rules the build enforces

Blank, never invented

If a value cannot be confirmed from an official source, the cell renders as UNVERIFIED. It is never estimated, interpolated or copied from a third party.

Derived is labelled

A value computed by pure arithmetic on official values (a total, a tally, a share) is permitted and is badged DERIVED so it is never mistaken for a read value.

Source on every data row

The build fails if a data row lacks a source URL. The only exemption is the requirement register, which is governance sourced from the brief (F-006).

Never marked verified without a check

A row is only badged verified where the value has been checked against the linked official source in this session.

Tier separation

Community data may be referenced but never populates a value.

Reproducible

Every register lives in a JSON file under /data and the site is generated from it, so any claim can be traced back to the exact file and row.

How to re-run this

The site is generated from the JSON data layer by a single command:

python3 tools/build_site.py

It re-reads every file in /data, re-runs the source assertion, rewrites every page in /docs, and prints any row that failed verification. If a data row is missing its source link, the build fails and names the row rather than publishing a sourceless table.
