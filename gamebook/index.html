Why this page exists

The repository's readiness register carried four rows blocked on the same missing source - an official inactive list, an official record of who actually started, and the Game Book itself, which was recorded as "source not identified". It is identified: every official game centre page links a "Download Game Book (PDF)" file, and page one of that document prints, for each club, the starting line-ups, the substitutions, Did Not Play and Not Active. Example, read 2026-11-16: the Patriots-Lions game centre links this PDF.

The league also publishes a dated weekly inactives article, which lists every club's inactives in one page: Week 10 of 2026. Two official sources for the same fact are captured separately and cross-checked; neither is inferred from the other.

The numbers, in one table

summary.html is generated rather than written: every row is read from the artifact named beside it at build time, so the page cannot keep an old figure after the data moves. A row whose artifact does not exist shows blank with the file that should hold it.

Reading the two lists together - the trap this register exists to publish

16 of 64 players marked Out on the weekly report do not appear on their club's game-day inactive list. A club's eight designations are spent on everyone else it is sitting, because an Out designation already makes a player ineligible. So not on the inactive list must never be read as available. In the same direction, 77 players on an inactive list have no row at all on the weekly report - healthy scratches, plus the reserve-list case recorded elsewhere on this site. A model whose availability universe is the injury report therefore treats 77 players as available who were not, and a feature built on "absent from the inactive list" would mis-state 16 Out players as available. Both counts are published per week in the ledger below.

Designated rows that could not be joined because no inactive list covers those clubs: 15 (clubs: BAL, LAC, NYG, WAS). Those rows are left unjoined in the ledger with the state no_inactive_source - they are not counted as available and not dropped.

Where each number came from

  • Weekly injury report (game-day designations): the committed CI capture data/model/official_injuries.json - 347 rows, 28 club tables for Week 10 - and, once the scheduled sweep has run, data/gamebook/captures/report/.
  • Game-day inactive lists: data/gamebook/official_inactives/ (transcribed, with the evidence text it was read from) and data/gamebook/captures/inactives/ (raw bytes, hashed).
  • Game Books: data/gamebook/captures/gamebook/, one capture per game with the PDF URL, the raw sha256, the UTC fetch time and the parsed lists.
