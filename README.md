# NFL1 — NFL decision-intelligence dashboard

**Live site:** https://kanlerxz87-cyber.github.io/NFL1/
**Data snapshot:** 2026 NFL regular season, Week 10, retrieved 2026-11-12 (UTC).

A clean, static GitHub Pages dashboard built from a JSON data layer. Every table row links to an official
source. If an official source publishes no value, the cell is left blank and the item is flagged on the
[Flagged for Review](flagged.html) page. No value is inferred or filled in.

## Rebuild and verify

```bash
python3 tools/seed_data.py              # regenerate data/*.json from transcribed official values
python3 tools/compute_correlations.py   # recompute Pearson r from official standings
python3 tools/verify_combined.py        # re-verify merged CSV snapshots and all local links
python3 tools/build.py                 # generate the HTML pages and docs/*.md
python3 tools/verify.py                # source links, unverified blanks, internal links
```

`tools/verify.py` and `tools/verify_combined.py` also run in GitHub Actions on every push and pull
request. GitHub Pages publishes `main / /`; `.nojekyll` keeps the generated HTML unchanged.

## Gates that must pass before anything merges

```bash
python3 tools/evidence_from_official.py   # rebuild the official fixtures
python3 tools/verify_official.py          # every repo dataset vs the official pages, cell by cell
python3 tools/build_decision_room.py      # recompute the verdicts
python3 tools/build_dashboard.py          # render web/ from JSON only
python3 tools/verify_dashboard.py         # independently reproduce every figure (383 assertions)
python3 tools/check_freshness.py          # no page is older than the data it shows
python3 tools/check_generators.py         # one writer per generated path
```

`verify_official.py` must report **0 failed**. Flagged rows are expected and are published on
the review page: a flag states that no official source confirms the value, which is a finding,
not a build error.

## Two conventions that are easy to get wrong

- **Line signs.** The model prints lines from the home team's point of view, so `ARI +5.2` in
  `LA @ ARI` is not "Arizona favoured"; it is the home-signed number. The market columns print
  both sides (`ARI -9.5 / LA +9.5`) and every difference is derived from the printed numbers,
  never re-typed. The one time this was violated the same row appeared to show a 14.7-point
  difference instead of 4.27.
- **Round once.** Model and market values are stored to two decimals; differences are computed
  from stored values, so a printed difference can differ from the difference of the printed
  values by 0.01. The dashboard computes from the printed numbers to avoid that.
