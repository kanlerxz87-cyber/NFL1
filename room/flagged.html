F-107 Two generators write index.html; the one that commits is not the one the pull-request check auditsProcess · minor open

`pipeline/gen_site.py` renders the evidence-first dashboard and the collect-data workflow commits its output to `index.html` and `pages/`. `tools/build.py` also writes `index.html`, from a different template and a different data layer; it runs in the 'Verify NFL1 site' pull-request job immediately before `tools/verify.py`. The consequence is narrower than a broken site but still real: the check that runs on every pull request audits a regenerated substitute rather than the page that is served, and any local or ad-hoc run of `tools/build.py` overwrites the front door in the working tree. Reproduced locally: running `tools/build.py` changes `index.html` by 345 insertions and 84 deletions; `git checkout -- index.html` restores it. The committed page on `main` is the correct one, because the bot commits only `pipeline/gen_site.py` output.

Official source

https://github.com/kanlerxz87-cyber/NFL1/actions

Where it shows up here

  • Committing writer gen_site.py then git add index.html pages
  • Pull-request writer tools/build.py before tools/verify.py
  • Existing flag F38 records the same hazard
What would settle itApply SG-12: build.py writes legacy-site.html; tools/verify.py reads the new name. Then the pull-request check audits the served page.
