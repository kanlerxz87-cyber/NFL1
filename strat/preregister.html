The rule

A backtest number may be published only when a registration record exists for the rule and the registration commit is an ancestor of the publishing commit. Enforced by tools/check_preregistration.py, which fails the build otherwise.

Enforced by tools/check_preregistration.py, which fails the build when a published result has no registration record, when a record's commit does not precede the result, or when a registered rule's exact text no longer appears in the generator that scores it.

What "registered-backtest" means, honestly

The twelve legacy rules were written before this session but after the scoring data existed. Registering them now does not make their backtest results prospective — it freezes them so that any future edit is a visible diff, and it discloses that twelve hypotheses were searched in one run, which the multiplicity charge in the leaderboard pays for. Presenting them as prospective would be the exact error this registry exists to prevent.
