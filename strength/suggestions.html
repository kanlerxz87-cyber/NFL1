A review queue, not a to-do list

Each suggestion states the problem, the options, a recommendation, cost, risk and what blocks it, so a reviewer can choose a path before anything is implemented. Nothing below has been implemented unilaterally; each is a path a reviewer can accept, reject or re-scope.

How to review a suggestion in two minutes

  1. Does the problem cite a number or a link you can check? If not, reject it.
  2. Does the recommendation change a published number? If so, the blast radius line matters more than the upside.
  3. If it is blocked, is the blocker a source, a budget, or a decision? Only the first two can be fixed by an agent.
