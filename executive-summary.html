Purpose and scope

The project brief asks for a complete requirements inventory, a decision gate built from what is known and unknown, a review-first suggestions section, original NFL lines and validated signal strategies run as a rewarded leaderboard competition across single bets, parlays and player prop combos, injury and second/third/fourth-string backup tracking for offense and defense, an executive summary, line-by-line verification against official sources, a GitHub Pages dashboard, and a fully autonomous pull-request-and-merge cycle.

This build delivers the documentation, the verified data snapshot, the site and the governance framework. It deliberately does not publish invented odds, scores, ranks, correlations or performance claims: no official source was found for those values, so the cells are blank and flagged.

Decision posture

No implementation decision has been taken. The Review & Choose a Path section presents three paths (data first, strategy first, review only). The advisory recommendation is Path A — Data first, because official state data shows parlays losing far more often than straight bets and NIST guidance requires unseen data before any performance claim. A reviewer must choose a path before anything is built; the choice is recorded locally in the browser and can be filed as a GitHub issue.

Own lines, signals and competition

The own-line pipeline is specified end to end using official inputs only (standings, schedule, injury report, club depth charts, player stats, Next Gen Stats). 10 candidate strategies cross single bets, parlays and player prop combos. Every strategy must pass 13 validation gates covering provenance, point-in-time data, pre-registration, minimum sample, out-of-sample testing, significance, multiple comparisons, correlation control, stability and reproducibility. All 10 strategies are currently NOT PASSED, so the leaderboard has no ranks or scores and only non-monetary reward tiers are proposed.

Correlation values that can be computed from official standings were computed with a committed script (for example, net points per game vs winning percentage: r = 0.8758, n = 32). All other correlations remain blank and flagged. NIST states explicitly that correlation does not imply causality, which is why gate G08 exists.

Injuries and backup depth

The official Week 10 injury report, the published Personnel (Injury) Report Policy filing schedule, the official Week 9 inactives list and three official club depth charts are transcribed into tables. Of 61 transcribed injury rows, only 6 publish an injury description or a game status. The depth charts publish 1st through 4th string for offense and defense, and the official inactives list contains explicit "emergency third QB" entries. Two of the three charts are labelled "Unofficial" by the clubs themselves and the league injury report publishes no depth-rank column, so a league-wide deficiency score is left blank and flagged.

Site and deployment

17 static pages, grouped navigation, sortable/filterable tables, responsive CSS and no external dependencies. A Python generator builds the HTML from the JSON data layer; an independent validator checks that every table row has an official source link, that unverified rows keep blank value cells, and that every internal link resolves. GitHub Pages is configured to publish main / /; a .nojekyll file keeps the plain HTML untouched.

Coordination and irregularities

The repository initially contained only a one-line README. A second agent session branch is active with overlapping task claims; this session kept disjoint file scopes, logged the conflict, and acted as the final integration session. 44 irregularities are published on the Flagged for Review page with official source links, including an unresolved template variable in the official standings heading and a conflict between the official injury report and official NFL.com news headlines.
